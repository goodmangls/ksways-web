## 2. Gap — Design v0.1 이 `opacity` 선언 위치 3곳 중 2곳만 다뤘다

### G-1 (근본, **Critical**) — 기본 규칙 누락

Design v0.1 §2.1 은 키프레임을, §2.2 는 reduced-motion 블록을 다뤘다. 그러나 `opacity` 는 **세 곳**에서 선언된다.

```css
.ks-hero-bg-attribution {
  opacity: 0;                                          /* ← 다루지 않음 */
  animation: ks-hero-bg-cycle 21s infinite;
  animation-delay: calc(var(--ks-slide-index) * 7s);   /* ← 양수 */
}
```

`animation-delay` 가 **양수**(0s·7s·14s)이고 `animation-fill-mode` 가 없다. 애니메이션이 시작되기 전 딜레이 구간에는 **키프레임이 적용되지 않고 기본 규칙이 적용된다.** 기본 규칙에는 `visibility` 가 없으므로 기본값 `visible` 이 되어, §2.1·§2.2 만 구현한 상태에서 **로드 후 14초간 FR-01 이 그대로 미충족**이었다.

**측정된 상태 (G-1 수정 전, 실브라우저)**:
```
[{i:0, opacity:1, visibility:"visible"},
 {i:1, opacity:0, visibility:"visible"},   ← 비가시인데 Tab 도달 가능
 {i:2, opacity:0, visibility:"visible"}]   ← 동일

Tab 순회 → attr#0, attr#1, attr#2 전부 도달 (6개 링크 모두)
```

**원인**: 초안이 대상을 "`opacity` 가 선언된 모든 곳"이 아니라 **"애니메이션이 정의된 곳"** 으로 잡았다. `animation-delay` 가 양수라는 사실이 설계 시 고려되지 않았다.

### G-2 (파생) — 가드가 같은 사각지대를 가졌다

Design v0.1 §2.4 의 가드 4건은 키프레임 블록과 reduced-motion 블록만 검사한다. G-1 이 살아 있는 상태에서 **13/13 GREEN 이었다.**

정적 가드를 설계할 때 "검사 범위 = 설계가 다룬 범위" 로 잡았기 때문이다. 설계가 놓친 곳은 가드도 놓친다.

### G-3 (파생) — §2.6 변경 파일 목록이 실제와 불일치

`globals.css` 변경을 "키프레임 3구간 + reduced-motion 4선언" 으로 적었으나 실제로는 기본 규칙 4선언이 더 필요했다.

### G-4 (파생) — §3 구현 순서에 해당 단계 부재

1~2 단계가 선언 위치 3곳 중 2곳만 커버한다.

## 5. 학습

1. **"애니메이션을 고친다" 가 아니라 "그 속성이 선언된 모든 곳을 고친다" 로 범위를 잡아야 한다.** `animation-delay` 가 양수면 딜레이 구간의 실효 스타일은 키프레임이 아니라 기본 규칙이다. `animation-fill-mode: backwards` 가 없다면 더더욱.

2. **정적 가드의 검사 범위를 설계 범위와 같게 잡으면, 설계가 놓친 것은 가드도 놓친다.** G-2 가 그 사례다. 가드는 "설계가 다룬 곳" 이 아니라 **"그 속성이 나타날 수 있는 곳 전체"** 를 훑어야 한다. 이번 수정본은 `.ks-hero-bg-*` 선택자를 전수 스캔한다.

3. **실브라우저 검증이 정적 검증의 대체재가 아니라 상위 검증이다.** 직전 사이클에서 "정적 단언이 타당한 대리" 라고 판단했고 그 판단 자체는 틀리지 않았지만, **대리의 범위가 좁으면 대리도 좁다.** 이번엔 Tab 순회가 아니었으면 결함이 머지됐다.

4. **결함 주입은 "주입이 실제로 일어났는지" 부터 확인해야 한다.** 주입 스크립트가 조용히 실패하면 "가드가 통과했다" 는 무의미하다. 제거된 줄 수를 단언하는 식으로 주입 자체를 검증할 것.
